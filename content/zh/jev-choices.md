# 决策模型，究竟能替 agent 做哪些判断？

<div class="meta">Jev / 第一篇 · 2026-09-21 · 约 9 分钟</div>

一个处理差旅报销问题的企业助手，通常要先搜索政策、打开文档、核对适用范围，最后给出带依据的答复。如果缺少影响报销资格的事实，还得先向用户询问。最终答案只是一部分工作；在它之前，系统需要连续决定下一步做什么。

在 ReAct 式 agent 中，通用语言模型承担这部分控制工作：结合任务和已有观察选择动作，程序调用工具，再把结果交回模型，继续判断。这个循环让系统能根据新证据调整方向，也意味着每经过一个决策点，都可能增加一次模型调用的等待和费用。本文用“ReAct 式”指这种根据反馈逐步行动的工作方式；[原始 ReAct 研究](https://react-lm.github.io/)讨论了推理与行动交替进行的设计。

Jev 的出现提供了另一种实现选择。[Jev 是 TypeSafe 的结构化决策模型](https://openrouter.ai/typesafe/jev-1.13)，面向软件中的分类、路由和有限选项判断。它让程序提交待判断的信息，并取得有类型的决策结果。对于“读哪份材料”“缺不缺前提”这样的步骤，一个直接做选择的模型，有没有机会接手通用语言模型的部分工作？这并不要求把整个 ReAct 循环换掉，而是先找出其中适合替换的判断。

本文研究的正是这个前提：**Jev 单独面对哪些问题时能选对，在哪些问题上会失败，返回的候选分数又能提供什么信息？** 实验先用可核验的合成规则与动作，再加入公开推理题和字符位置任务。结果显示，Jev 在所测短规则与证据适用性任务上表现良好；复杂布尔推理和逐字符选择则出现了明确错误。候选分数提供了一些排序线索，但还不能当作可靠的正确概率。

这里先不让另一个模型补救 Jev 的错误，也不把它接进完整工作流。只有把单体的成功条件和失败案例分清，才能判断哪些地方值得做 [Jev / Luna 对照](@/projects/jev-comparison/)，再进一步测试[完整 agent](@/projects/jev/)。

## 怎样把“下一步做什么”变成可测的问题

本研究使用 Jev 的 **Choice** 问题类型。可以把它理解为一次带上下文的单选判断：开发者提供事实、判断要求和候选，模型返回选择。Choice 是这里使用的输入输出方式，不是一个会自己搜索、操作工具或完成任务的 agent。[官方接口说明](https://docs.typesafe.ai/primitives/choice)介绍了这种输入输出方式。

在实验里，一次判断由下面几部分组成：

| 部分 | 表达什么 | 在报销检索场景中的作用 |
|---|---|---|
| 当前状态 | 本次能看到的事实与证据 | 用户问题、旅行事实、搜索摘要和已打开正文 |
| 判断要求 | 应按什么规则选择 | 有适用正文则作答；只有适用摘要则先读；否则继续找 |
| 候选动作 | 合法选项及各自含义 | 搜索、读文档、询问缺失事实、作答 |
| 返回结果 | 选中的候选及各候选权重 | 程序可据此分派动作；本篇只检查选择是否正确 |

前面提到的报销助手，在这里被做成了一个**本地合成测试场景**。模型看到的资料由实验预先给定，不访问真实企业系统。选择“作答”仅表示模型认为已经可以回答；实验并没有因此生成或验证一份报销答复。

这种拆法把“判断”从搜索质量、参数生成和执行结果中分离出来。预期正确选项先依据题目规则确定，再调用 Jev；判断结果既要通过接口校验，也要和预期答案一致。返回了合法 ID 却选错，与调用根本没有得到有效响应，是两类不同问题。

## 研究手法：逐步增加判断里需要完成的工作

实验没有把所有选择题混成一个总分，而是分别检查几类能力。

最开始，题目给出短事实和明确动作。随后修改干扰选项、删除直接写出的结论、移动正确项位置，观察模型是否仍能按规则选择。政策场景再固定文档数量和外观，只改变文本的适用范围，减少“看见文档就作答”这样的捷径。

接下来引入公开推理题，检查模型能否先算出结果，再选择对应标签。最后把字符作为候选，观察把文本输出拆成选择之后，位置判断能否可靠完成。这几组各有自己的输入、分母和失败解释。

| 实验 | 设计与样本 | Jev 正确数 |
|---|---|---:|
| 短动作与规则 | 六个任务族、12 个变体，各重复两次 | 24/24 |
| 政策适用性 | 四种证据状态、两种措辞，各重复三次 | 24/24 |
| BBH 公开推理 | 三个任务族，各抽六道不同题 | 17/18 |
| BBEH 复杂表达式 | 六道不同题，每题五个表达式 | 2/6 |
| 下一字符，隐藏目标词 | 两个短词、六个字符位置，各重复两次 | 8/12 |
| 下一字符，给出目标词 | 相同位置与重复次数，增加目标词 | 10/12 |

这些分母不能相加来估计“Jev 总体准确率”。重复同一道题能观察同输入的表现，却不会增加独立业务问题的覆盖。表中的政策单体探查与第二篇的匹配对照沿用了同一题目设计，但使用不同批次的调用，也分别记录。

## 短规则能选对，但成功范围需要说清

最初的动作题包括区分修改账单地址与修改收货地址、暂停订阅与永久取消，以及根据保修或退货例外决定动作。部分题直接给出结论，另一些移除结论，要求模型从保留的事实和规则推导。12 个变体各重复两次，Jev 全部选对。

不过，三个语义选择任务的正确项起初都排在首位。为了检查位置捷径，另做了六次顺序诊断，把这三个任务的正确项移到末尾，仍为 6/6。它排除了这些题上“只选第一项”的简单解释，但没有证明任意候选顺序都可靠。这六次也没有并回原来的 24 次。

政策题进一步追问：Jev 是判断了证据含义，还是只看到了资料齐全？实验始终给出两个搜索命中和一篇已打开正文，并固定标题、日期和文档标识。只改变搜索摘要、正文分别适用于普通出差还是员工搬迁。两个版本都出现相关主题词，因此“有没有提到出差”不足以解题。

| 已有证据 | 按给定规则应该做什么 |
|---|---|
| 有适用且足以回答的正文 | 作答 |
| 正文不适用，但搜索摘要指向适用材料 | 打开那份材料 |
| 正文和搜索摘要都不适用 | 继续搜索 |

这里的搜索摘要只提供文档入口，不能替代正文。用户事实已经完整，所以“询问用户”是一个合法但不正确的候选。四种适用性组合、两种等义措辞、每种三次调用，Jev 为 24/24。仅按“正文非空就回答”的字段规则，在这组题上只能命中 12/24。

这支持了一个具体能力：在明确路由规则下，依据短文本的适用范围选下一步。它还没有覆盖真实检索噪音、多份政策互相冲突、版本效力或引用生成。针对这些固定句型写一个专用解析器，也可能完成测试。因此，这里找到的是值得继续比较的任务类型，而不是已经证明模型优于代码。

## 当选择之前还需要复杂计算

规则题的成功留下了一个问题：Jev 是否只能识别已经很接近答案的动作，还是也能完成更复杂的计算？为此，下一批改用公开推理题集 **BIG-Bench Hard（BBH）**。实验在调用前，从逻辑排序、物件交换追踪、布尔表达式三个任务族各抽六题，没有依据模型表现挑题。

Jev 在排序和交换追踪上各答对 6/6，在布尔表达式上答对 5/6，总计 17/18。这说明它在这些题上可以完成超出直接动作匹配的判断。不过，每个任务族只有六题，不能由此得到宽泛的推理能力排名。

更难的 **BIG-Bench Extra Hard（BBEH）** 测试使用六道五选一布尔题，每个选项本身都是一个完整表达式，只有一个为真。Jev 六次都返回了有效选项，却只答对 2/6。五个候选并不多，真正的难度在于选标签之前必须完成的逻辑计算。

字符实验从另一个角度检查同一问题：如果把生成字符串改成逐次选择字符，能否沿用决策模型？测试使用两个三字母英文词，每次都提供正确前缀，让 Jev 从包含字母及结束项的 28 个候选中选下一步。这样，前面一个字符出错不会污染后面的测试。

只计字符位置时，隐藏目标词为 8/12，给出目标词为 10/12。即使输入已经包含目标 `dog` 和正确前缀 `d`，Jev 仍两次把下一个字符选成 `g`，而不是 `o`。这不是工具执行问题，也不是此前生成错误累积的结果。

词尾结束另计，两种条件均为 4/4。两个短词和重复位置不足以证明普遍的字符能力边界，更不能反推模型架构；它们确实提供了反例：把任务写成选择题，并不会自动让其内部计算变简单。

## 候选分数还告诉了什么？

除选项外，Choice 还返回候选分布。为了分析它，将最大候选权重记为 `pmax`，再检查正确项的排名。这里要检验的是：这些数字能否帮助识别不可靠的选择，或保留一个值得复核的替代答案。

BBH 的唯一错误返回了 0.50 / 0.50 的分布，看起来确实犹豫。但另一个答对的交换追踪题，最大权重也只有 0.48。低分可能伴随错误，也可能拒绝本来正确的答案。

首批 BBEH 上，两道正确题的最大权重是 0.50 和 0.37；四道错误题则在 0.41 到 0.53 之间。两组明显重叠。若把 0.90 设成自动接受门槛，这六题会全部被拒绝，既拦住错误，也留下不了任何自动处理的题。

排名提供了另一条线索：四道 BBEH 错题中，正确项有三次排在第二，一次排在第四。保留前两项可能保住部分答案，但它只说明候选还在，不能说明后续一定选得对。在只有两个候选的 BBH 布尔题里，“正确项进入前二”更是必然成立，不能算额外收益。

本研究没有证明候选权重经过正确率校准——也就是分数为 0.90 的判断，是否真能在新任务中约有九成正确。它适合先当作待验证的控制信号；实际转交之后能否省钱、纠错，会在[单点对照与转交实验](@/projects/jev-comparison/)里继续检验。

## 这些结果怎样改变 agent 的设计选择？

回到开头的报销助手：已有事实和规则较短、动作范围明确时，Jev 有理由成为下一步选择器的候选。这类任务值得继续比较同质量下的成本和耗时。精确的日期运算、字段复制与可直接计算的条件，则可以交给代码。

遇到复杂推理，或想靠逐字符选择生成文本，当前实验已出现具体失败；不能因为返回格式总是合法，就把这些工作一并迁给 Jev。返回分数也尚不能保证自动执行可靠。

因此，这一阶段的结论是有条件的：**Jev 值得优先用于规则明确、事实已给出、结果可核验的有限动作判断；更复杂的计算和生成需求需要另作处理。** 这是一组小规模能力探查得到的设计起点。它没有证明 Jev 普遍替代通用语言模型，也没有证明局部全对就能组成可靠的 ReAct 替代系统。
