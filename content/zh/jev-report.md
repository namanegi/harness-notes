# Jev 实验附录

<div class="meta">探索性研究 / 2026-09-20—21 / Jev 1.13 · GPT-5.6 Luna</div>

[第一篇：Choice 能力与候选分数](@/projects/jev-choices/) · [第二篇：Jev／Luna 单点对照](@/projects/jev-comparison/) · [第三篇：完整工作流](@/projects/jev/)

**短规则路由里，Jev 有便宜、快速的观察结果；复杂推理和多步搜索并没有自动获得同样收益。**我们先做单步能力探针，再比较 Luna，最后检验转交、DOM 搜索和完整工具工作流。

这是一份公开报告摘编。样本小、部分人工合成、每条件 rollout 少，不是模型排名或部署可靠性估计。[下载公开汇总表](@/assets/jev-evidence.json)。

## 方法与公开范围

Jev 通过官方 OpenRouter Python SDK Decisions 接口调用；Luna 用官方 OpenAI SDK 的严格 JSON 输出，ReAct 用 Agents SDK。相关 SDK 批次使用 TLS 验证、连接复用和零自动重试。Jev 返回版本为 `typesafe/jev-1.13-20260917`；Luna 请求 `gpt-5.6-luna`。

选择正确、结构合法、达到目标状态和显式停止分别计数。Jev 费用取 API 报费，Luna 根据输入、缓存读写和输出 token 估算；均未与供应商账单核销。墙钟包含本地和网络开销，不是纯推理时间。

公开题来自固定版本的 [BBH](https://github.com/suzgunmirac/BIG-Bench-Hard/tree/9ee07bd481feebf959a6b59d61ea57bdcf30964d) 和 [BBEH](https://github.com/google-deepmind/bbeh/tree/80d12ca916b7158f22293fcf3144f4d3d854d4be)。先按固定种子抽题再调用，BBH 布尔与交换题另由代码核验 gold。未知训练重叠、题量和任务混杂限制推广；没有在这页重新分发题目原文。原始账本、完整输入和 runner 没有随博客公开，因此这些汇总支持检查报告的算术与分母，不构成完整独立复现包。

## 1. 候选少，不等于推理简单

### 单体合成探针

以下调用早于匹配的 Jev／Luna 对照。政策探针和后来的模型对照沿用同一题目设计，但属于不同调用批次。

| 探针 | 设计 | Jev 有效／正确 |
|---|---|---:|
| 简短动作与规则 | 六个任务族、12 个变体，各两次 | 24/24 有效；24/24 正确 |
| 独立的选项顺序诊断 | 三个语义选择变体，把正确项移到末尾，各两次 | 6/6 有效；6/6 正确 |
| 政策适用性 | 四种证据适用状态、两种措辞，各三次 | 24/24 有效；24/24 正确 |

短规则探针改变动作说明，以及是否直接给出规则结论；顺序诊断不合并进主批分母。政策探针固定文档数量和元数据，只改变摘要与已打开正文的适用范围，用户事实完整。它测选择动作，不测检索和最终答案生成。API 报告费用依次为 $0.000452088、$0.000104496、$0.000895104；汇总项为 `single_rule_actions`、`single_rule_order_diagnostic`、`single_policy_applicability`。没有运行有竞争力的代码基线，专门针对这些规则句型的解析器也可解题。

### 不同动作状态与公开推理题


| 同题条件 | Jev 正确 | Luna 正确 | 解释 |
|---|---:|---:|---|
| 14 个不同短规则动作状态 | 14/14 | none：14/14 | 同一观察质量下可比较费用和时间 |
| BBH 三类各六题 | 17/18 | none：11/18；low＋步骤提示：17/18 | 不能用最低推理配置概括 Luna |
| BBEH 原六道五选一题 | 2/6 | low／1024：2/6；low／4096：4/6 | 原 1024 限额只有三个有效答案 |

14 个动作状态中，Jev 总费 $0.000305592、请求耗时中位数 485 ms；Luna none 总费 $0.000882800、中位数 1,470 ms。Luna 缓存读写均为零。这一小批动态状态不依赖精确请求重放。

BBH low 配置同时改变步骤提示、effort 和输出预算，且跨批补齐，不能作纯 effort 归因。BBEH 的提高额度诊断对原六题全部执行，恢复了六次有效响应，但仍有两题错误。BBH 与 BBEH 同时改变嵌套、知识、长度和运算组成，未定位单一深度阈值。

英文 `red`、`dog` 字符位置探针的 28 候选中，隐藏目标为 8/12，给出目标为 10/12；已知 `dog` 和前缀 `d` 时仍两次把下一字符 `o` 选成 `g`。这些是两个词上的重复位置判断，完整词后的 STOP 另计。它说明语义动作识别与序列位置计算不能互相替代，也不能归因于某个未经验证的内部模型架构。

## 2. 低分转交：纠错也会改错

先在不同题上探索分数，再固定 `pmax≥.90` 接受 Jev，否则实际调用 Luna。新批抽六道 BBH 和六道 BBEH，排除已用索引；这是刻意的压力混合，不代表部署比例。独立 always-Luna 逐题调用，先后顺序交替，Luna 均为 low／4096。新批使用显式缓存且无断点，实际读写均为零。

| 新题组 | Jev 直接 | 转交系统 | 独立 Luna | 转交费用 | 独立 Luna 费用 |
|---|---:|---:|---:|---:|---:|
| BBH 六题 | 5/6 | 5/6 | 6/6 | $0.000550038 | $0.001723400 |
| BBEH 六题 | 2/6 | 3/6 | 2/6 | $0.007627226 | $0.004370600 |
| 固定混合 12 题 | 7/12 | 8/12 | 8/12 | $0.008177264 | $0.006094000 |

三题直接接受且全对，九题转交。Fallback 纠正三个 Jev 错误，也把两个正确选择改错。全部 BBEH 都转交，所以两批 Luna 的质量差只是独立生成波动，不能归给筛选器。转交系统费用更高，尚未证明通用门槛有收益。

另在六道新 BBEH 保留 Jev top-2 再交 Luna，gold 只保留 4/6，最后原题正确 3/6。独立完整策略费用约 $0.007917426；本实验复用了已有 Jev 分布，研究账本没有重复收费。筛掉正确答案后，知道“两项皆非”也无法恢复原题答案。

## 3. 树形选择与同模型复核

早期七个固定 DOM 状态里，扁平 Jev 为 7/7，逐层贪心为 6/7。后续加入局部拒选、回溯与候选复核。首批两个缺失页有标题和路径冲突，保留评分歧义；另冻结事实一致的四个页面，无目标条件真正删除目标元素。

| 一致事实四页 | 终态正确 | 模型调用 | 总费 |
|---|---:|---:|---:|
| Jev 扁平 | 4/4 | 4 | $0.000183498 |
| 局部路由＋回溯＋复核 | 2/4 | 20 | $0.000378672 |

回溯在两个无目标页都误点：把年度套餐当试用套餐、把 Direct 渠道当 Partner。复核看到完整祖先仍接受，显示同模型再次判断不能保证全部约束成立。另一个精确标题无目标页没有误点，但耗尽 15 次调用后未解决，不能算正确 `none`。精确字符串和路径条件的代码基线无需模型即可完成该对照。

这些是固定 HTML 的本地动作模拟，不包含真实浏览器导航或点击可执行性。路径权重也不是已校准的最终成功概率，未展开部分不能悄悄消失。

## 4. 完整工作流与充分参数上下文

四个短任务包含政策检索、备仓预留与两种验证反馈。已知字段由代码复制，Jev 选择有限动作，Luna 只生成查询和说明。所有成功终态另行核验，不向运行时返回 gold。

| 配置 | 正确终态且结束 | 模型调用 | 四题总费 | 四题墙钟合计 |
|---|---:|---:|---:|---:|
| Luna Agents SDK ReAct | 4/4 | 20 Luna | $0.004205870 | 44.751 s |
| bounded Plan，独立严格枚举修正批 | 4/4 | 10 Luna | $0.002867550 | 26.669 s |
| Jev＋Luna 全上下文填参 | 4/4 | 16 Jev＋4 Luna | $0.001594020 | 13.239 s |
| Jev＋Luna 充分精简填参 | 4/4 | 16 Jev＋4 Luna | $0.001146214 | 12.231 s |

原 Plan 的字符串 schema 允许自然语言步骤，执行器只接受动作 ID，造成工具执行前四格接口失败。保留原记录后，仅收紧为严格枚举并独立跑完整四题；其计时是后续批次。两个任务用了一次有界重规划，不能将成功归于初始静态计划。

充分精简的 Luna 参数输入从 2,888 降至 1,319 token，总费约低 28%，四题都成功；它保留完整选中工具契约。完整视图另有 1,057 缓存写入 token，费用差也包含计费结构变化。ReAct 在 stop 后还生成最终回复，其他控制器直接退出；这些是具体系统结果，不是等步骤纯模型速度排名。

## 5. 条件分解：可诊断不等于可靠验证

两个已知错误作开发例，另冻结八个新候选。在同一原始目标与候选事实下，一次整体 Jev 判断为 6/8；同次请求三字段 Choice、由代码合取为 7/8。分字段修复了缺少状态却接受的错误，仍把 Direct 渠道当 Partner，字段本身只有 21/24 正确。Luna low 的同题严格字段 JSON 为 8/8 最终判断、24/24 字段正确。

分字段 Jev 八次 $0.000251790，Luna 八次估算 $0.001000400。两者未达到相同观察质量；不能仅按便宜排序。

单点达到了预先规定的有限推进条件，于是另冻结四个 DOM 页面。扁平 Jev 4/4、四次调用；整体复核树与分字段复核树均 3/4、各 27 次。唯一失败页中，前者耗尽预算未解决，后者误点。分字段树总费 $0.000622230，扁平 $0.000185556。多字段输出暴露了错误位置，但没有带来完整系统收益；同请求的多个字段也不是统计独立的证据。

## 6. 八个新工作流：便宜仍有质量代价

统一停止工具立即退出后，新实验用政策、库存、访问与事故四类各两题。四题可完成业务，四题必须请求补充；请求补充与业务完成分列。生成的查询真实影响模拟文档或日志检索，已知字段由代码复制。它们仍是合成封闭任务，不是真实服务或公开 benchmark。

| 原八题批次 | 正确处置且结束 | 业务完成 | 正确请求补充并结束 | 总费 | 每格耗时中位数 |
|---|---:|---:|---:|---:|---:|
| Luna ReAct | 8/8 | 4/4 | 4/4 | $0.007095 | 7.38 s |
| bounded Plan | 7/8 | 3/4 | 4/4 | $0.007954 | 9.35 s |
| Jev＋充分参数上下文 | 7/8 | 4/4 | 3/4 | $0.002751 | 3.44 s |

原 Jev 在一题中正确请求审批补充，却反复动作不结束。其停止指令比另外两配置含糊，所以另冻结仅明确停止条件的 Jev 配置，完整重跑八题。仍为 7/8、费用 $0.002246、中位数 2.74 s：访问题成功了，事故题却在提前请求部署 ID 被拒后，查到日志便结束，漏掉再次请求必要信息。它没有猜造部署 ID 或回滚。

两批分别保留，不能挑每题最优拼成 8/8；不同时间的重复也不能将差异全归因于措辞。Jev 有记录费用优势，但没有达到本批 ReAct 的观察质量。明确的结束与工具拒绝后的恢复，仍需要 harness 处理。

## 7. 单点匹配对照

单点对照在每组 Jev／Luna 配对内固定决策事实、候选动作及顺序。Jev 使用 Choice，Luna 使用 Responses 的严格 JSON 枚举；gold 动作由调用前确定的规则给出。这里测的是有效选择、Jev API 报费、按 Luna 用量估算的费用，以及客户端端到端耗时，并未执行完整政策或报销流程。

**文档适用性。** 四种适用状态各写成两种等义措辞，每个变体重复三次，每配置共 24 次调用、八个设计变体。Jev **24/24** 正确。最初的 Luna `none` 把指令嵌在仿照 Jev 结构的用户 JSON 中，为 **13/24**。后来另行冻结的控制将相同指令移到原生 `instructions`，同时移除协议包装，Luna `none` 提高到 **21/24**。原生 `low` 还把输出上限从 128 提到 1,024 token，达到 **23/24**。13/24 到 21/24 是封装组合变化，不能只归因于一个字段；23/24 又同时改变 effort 和额度。原生指令条件下剩余的错误都来自“两份文档都不适用”的一种措辞。Jev 24 次总费 $0.000895；三种 Luna 配置估费分别为 $0.002994、$0.002953、$0.003606。原生控制在另一会话运行，其耗时不能与先前 Jev 批次重新组成配对速度比较。

**例外条款。** 四种逻辑状态分别要求作答、读附录、询问缺失授权、搜索附录；每种提供长短两档上下文，并各重复三次，每配置 24 次调用。Jev、原生 Luna `none`、原生 Luna `low` 均为 **24/24**。批次费用依次是 **$0.002862**、**$0.005341**、**$0.006625**；客户端耗时中位数为 **442.9 ms**、**1,335.5 ms**、**1,733.5 ms**。长档增加无关档案条目，也把相关证据推后，因此不是纯长度干预。长输入被原样重复：Luna `none` 写入缓存时的单次估费中位数约 **$0.000636**，后续读取约 **$0.000067**；对应的 Jev 长档调用约 **$0.000180**。在这组精确回放中，热缓存的 Luna 读取比 Jev 单次便宜，但 Jev 整批总费仍较低。工具结果不断改变的 agent 未必有相同缓存命中；Jev 也没有报告可比的缓存读写分项。

**变化的状态。** 第三组把 14 个不同短规则状态分别交给两个模型各一次。其中六个是先前成功的探针状态，八个新的保修与工作空间状态在本批看到结果前已冻结；同一任务族中，事实变化会改变必需动作。Jev 与 Luna `none` 均为 **14/14**。Jev 总费 **$0.000305592**、客户端耗时中位数 **485 ms**；Luna 估费 **$0.000882800**、中位数 **1,470 ms**，记录到的缓存读写均为零。这是变化请求下有用的费用观察，但六个开发案例和八个新合成案例不能拼成生产错误率；两者都没出错，也无法测出升级转交的收益。

这三组说明，指令封装和缓存状态会实质改变质量与费用的解释。重复调用不是独立业务任务，客户端耗时还包括不同供应商的网络和协议路径。[单点对照文章](@/projects/jev-comparison/)进一步讨论这些工程含义。

## 工程判断与限制

优先让代码承担字段复制、精确过滤和可计算规则；让决策模型承担经过任务检验的有限语义分叉；生成模型只看充分契约与必要观察。终态判断、缺失信息、停止和预算耗尽需要明确的不同定义。

这些发现定位了失败并验证部分设计设想。它们还不足以证明概率校准、真实业务可靠性或长工作流迁移。本页保留前批和追加诊断各自的分母。后续八任务与字段分解结果进一步限定了早期成功的适用范围。

接口参考：[TypeSafe Choice](https://docs.typesafe.ai/primitives/choice)、[OpenRouter Jev](https://openrouter.ai/typesafe/jev-1.13)、[OpenAI 缓存文档](https://developers.openai.com/api/docs/guides/prompt-caching)。页面定义与营销主张不替代本地实验。

## 运行与计量备注

- **Choice 字段。** 输入的 `state` 是当前事实，`instructions` 是判断规则，`criteria` 是候选及其含义。分析中的 `pmax` 是返回候选权重的最大值，与 API 另报的 `confidence` 字段不同；本研究没有验证任一数值的正确率校准。
- **匹配调用。** SDK 批次复用连接、验证 TLS、关闭自动重试；模型对照中相邻调用供应商，交替或轮换顺序。例外题的三配置轮流占据首、中、尾位置。序列化、token 统计、供应商与网络路径仍有差异。
- **缓存。** 14 个变化状态及十二题转交批次中，Luna 缓存读取、写入均为零。例外题长输入的热缓存费用另列于第 7 节；缓存记录属于对应批次，不能作为部署命中率估计。
- **转交预算。** 原六道 BBEH 的 Luna low／1,024 token 条件只有三个有效答案、2/6 正确；对全部六题提高到 4,096 后为六个有效答案、4/6 正确。新转交对照两条 Luna 路径均采用 low／4,096，并交替调用顺序。
- **四题上下文对照。** 每种 Jev 配置合计 16 次动作判断、4 次 Luna 填参。参数输入从 2,888 降为 1,319 token；完整视图另记录 1,057 缓存写入 token，调用顺序也不同。总墙钟约 13.2 与 12.2 秒，不能单独归因于上下文长度。
- **停止指令修订。** 原八题批次 Jev 调用 51 次，后续完整重跑为 40 次；总费约 $0.002751 → $0.002246，每题耗时中位数 3.44 → 2.74 秒。两批均为 7/8，失败题不同；这些是独立运行的观察值。
